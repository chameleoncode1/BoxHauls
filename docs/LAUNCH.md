# Launch checklist

Kickoff Prompt 5 item 3. Run through this in order before DNS cutover; nothing here should be started until `npm run qa`, `npm run links`, and `astro check` are all clean on `main`.

## 1. DNS cutover (Cloudflare Pages)

The `_redirects` map (`dist/_redirects`, generated by `scripts/generate-static-files.mjs` from `build_map.py`'s `REDIRECTS`) assumes Cloudflare Pages.

1. Add `boxhauls.com` as a custom domain on the Cloudflare Pages project; Cloudflare issues the SSL certificate automatically once DNS validates.
2. Point `boxhauls.com` (apex) and `www.boxhauls.com` at the Pages project per Cloudflare's own instructions for the domain's current DNS provider.
3. Confirm `_redirects` deployed correctly: `curl -I https://boxhauls.com/how-it-works` should return `301` with `Location: https://boxhauls.com/how-it-works/`.
4. Confirm the `www` → apex redirect: `curl -I https://www.boxhauls.com/` should return `301` with `Location: https://boxhauls.com/`.
5. Keep `truck-n-go.com` (the old domain) live and pointed at its own redirect rules for **at least 12 months** per map §12 — do not let it lapse or point it anywhere else during that window.

## 2. Search Console verification (both domains)

Verify **both** `boxhauls.com` and `truck-n-go.com` in Google Search Console and Bing Webmaster Tools — the old domain needs verification too, so its redirects get crawled and the link equity transfers instead of just expiring.

1. Add `boxhauls.com` as a Search Console property (domain property, not URL-prefix, so it covers `www` and apex both).
2. Verify via DNS TXT record (works for both Search Console and Bing without touching site code) or the existing `<meta>`/HTML-file method if DNS access isn't available to whoever runs this step.
3. Submit `https://boxhauls.com/sitemap.xml`.
4. Repeat verification for `truck-n-go.com` if not already verified from before the rebrand — this is what lets Search Console show the redirect chain is working rather than just reporting 404s on the old property.

## 3. Redirect test commands

Run every rule in `dist/_redirects` after cutover. Generated from the same source (`build_map.py`'s `REDIRECTS`) so this list can't drift from what's actually deployed:

```bash
for path in \
  /how-it-works /pricing /faq /contact /press /drive /partners \
  /link-to-us /blog \
  /services/on-demand-moving-and-hauling /services/furniture-delivery \
  /services/large-item-delivery /services/move-furniture \
  /services/single-item-movers /services/same-day-delivery \
  /services/local-hauling /services/truck-and-driver-for-hire \
  /services/small-moves /services/junk-hauling \
  /cities /cities/fresno \
  /cost-to-move-a-couch /cost-to-move-a-mattress \
  /cost-to-move-a-refrigerator /cost-to-move-a-washer-and-dryer; do
    echo "=== $path ==="
    curl -sI "https://boxhauls.com$path" | grep -iE "^(HTTP|location)"
done

# www -> apex
curl -sI "https://www.boxhauls.com/" | grep -iE "^(HTTP|location)"
```

Every line should show `HTTP/2 301` and a `location:` header pointing at the resolved target in `dist/_redirects`. Spot-check a couple of the `/blog/*` and `/cities/*` wildcard rules manually (e.g. `/blog/some-old-post-slug`, `/cities/austin`) since the loop above only covers exact-match rules.
