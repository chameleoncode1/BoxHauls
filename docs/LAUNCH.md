## 1. DNS cutover (Cloudflare Pages)

The `_redirects` map (`dist/_redirects`, generated by `scripts/generate-static-files.mjs` from `build_map.py`'s `REDIRECTS`) assumes Cloudflare Pages.

1. Add both `boxhauls.com` (apex) and `www.boxhauls.com` as custom domains on the Cloudflare Pages project; Cloudflare issues the SSL certificate automatically once DNS validates for each.
2. Point both at the Pages project per Cloudflare's own instructions for the domain's current DNS provider.
3. **`www` → apex is NOT in `_redirects`.** Cloudflare Pages' `_redirects` format only accepts relative-path sources (no hostname) — a rule like `https://www.boxhauls.com/* -> https://boxhauls.com/:splat` fails Cloudflare's deploy-time validation with `Invalid _redirects configuration: Only relative URLs are allowed` (hit and fixed during this project's first deploy attempt). Instead, once both domains above are added, create a **Redirect Rule** at the zone level: Cloudflare dashboard → the `boxhauls.com` zone → **Rules → Redirect Rules → Create rule** — When incoming requests match hostname equals `www.boxhauls.com`, then Dynamic redirect to `concat("https://boxhauls.com", http.request.uri.path)`, status code 301, preserve query string on.
4. Confirm `_redirects` deployed correctly: `curl -I https://boxhauls.com/how-it-works` should return `301` with `Location: https://boxhauls.com/how-it-works/`.
5. Confirm the `www` → apex Redirect Rule from step 3: `curl -I https://www.boxhauls.com/` should return `301` with `Location: https://boxhauls.com/`.
6. **Done (2026-09-26).** `truck-n-go.com` is hosted on Lovable; a domain-level redirect was configured there sending `truck-n-go.com/*` → `https://boxhauls.com/*` (path preserved) as a 301. Verified end-to-end: `truck-n-go.com/cost-to-move-a-couch` → `boxhauls.com/cost-to-move-a-couch` → `boxhauls.com/pricing/cost-to-move-a-couch/` (this repo's own `_redirects` catching the renamed path) lands on the correct final page. `www.truck-n-go.com` also redirects (via apex first). Keep this live for **at least 12 months** per map §12 — do not let the domain lapse or repoint it during that window.

## 3. Redirect test commands

Run every rule in `dist/_redirects` after cutover. Generated from the same source (`build_map.py`'s `REDIRECTS`) so this list can't drift from what's actually deployed:

```bash
for path in \
  /how-it-works /pricing /faq /contact /press /drive /partners \
  /link-to-us /blog \
  /services/on-demand-moving-and-hauling /services/furniture-delivery \
  /services/large-item-delivery /services/move-furniture \
  /services/single-item-movers /services/same-day-delivery \
  /services/local-hauling /services/truck-and-driver-for-hire \
  /services/small-moves /services/junk-hauling \
  /cities /cities/fresno \
  /cost-to-move-a-couch /cost-to-move-a-mattress \
  /cost-to-move-a-refrigerator /cost-to-move-a-washer-and-dryer; do
    echo "=== $path ==="
    curl -sI "https://boxhauls.com$path" | grep -iE "^(HTTP|location)"
done

# www -> apex
curl -sI "https://www.boxhauls.com/" | grep -iE "^(HTTP|location)"
```

Every line should show `HTTP/2 301` and a `location:` header pointing at the resolved target in `dist/_redirects`. Spot-check a couple of the `/blog/*` and `/cities/*` wildcard rules manually (e.g. `/blog/some-old-post-slug`, `/cities/austin`) since the loop above only covers exact-match rules.
